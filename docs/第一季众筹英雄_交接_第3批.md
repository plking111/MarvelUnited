## 5. 拖拽排序 UI（裁定 2）——数据流与取证

**数据流**（单机与联机同一条路）：

```
use_symbol/effect → trigger_effect() → "adamwarlock_quantum_magic" 分支
  → Game._ask_quantum_magic_order(hid)         # 取牌堆顶 3 张"真正的行动牌"（跳过宝石卡），记住它们的下标
    → Game._prompt("reorder", {cards, villain, title, public_title}, hid)
      → Net.broadcast_prompt(...)              # 联机：分发给各端
      → Game._emit_prompt("reorder", payload)  → Events.prompt_reorder(cards, villain, title, callback)
        → Board.gd: Events.prompt_reorder.connect(_popup.show_reorder_prompt)
          → PopupLayer.show_reorder_prompt()   # 3 张卡横排 + 残影跟手 + 悬停高亮 + 确认顺序
      ← callback(order) → Game._on_reorder_answered → _reorder_answered 信号 → 协程继续
    → Game._validated_permutation(order, cards) # 只接受同一批牌的排列，否则原顺序
    → 写回 state["master_deck"] 的原下标位置（宝石卡原位不动）
```

**UI 实现要点**（`src/ui/PopupLayer.gd`，`# ==== 拖拽排序弹窗（术士亚当·量子魔法）` 一节）：

- `show_reorder_prompt(cards, villain, title, callback)`：与既有弹窗同款外壳（遮罩 + 居中面板 + 标题 + 提示行 + 按钮），额外加：3 个 `PanelContainer` 槽位（`#1 牌堆顶` / `#2` / `#3`，内含 `UiKit.villain_action_image(villain, idx)` 卡图）+ 一个"残影" `TextureRect`（最后 add_child → 画在最上层）。
- 真拖拽：每个槽位 `gui_input` → `_reorder_slot_input(event, idx)`。按下 → 残影贴到鼠标位置并显示、被拖的槽位变暗；移动 → 残影跟手 + 悬停槽位高亮（换 `panel_style` 底色）；松开 → 与鼠标所在槽位**互换**（`_reorder_cards` 里换元素并重刷贴图）。
- **坐标一律用事件自带的 `global_position`**（不是 `get_global_mouse_position()`）：后者读的是真实 OS 光标，合成事件/自动化截图会算错落点，而且真机上也更准。
- 确认按钮 → `_reorder_finish()` → 回调新顺序；`hide_all_prompts()` 里一并清掉本弹窗的节点与状态。
- **无 UI 兜底**：`autopilot` 或 `Events.prompt_reorder` 没有任何连接时，`_ask_quantum_magic_order()` 直接保持原顺序返回（否则 `await` 会永久挂住 → 无头测试会被看门狗判死）。

**联机口径**（`src/autoload/net.gd`）：

- `broadcast_prompt()` 里对新加的 `_prompt_payload_for(kind, payload, can_answer)`：`kind == "reorder"` 且该端**不是**该答的人 → 下发**去掉 `cards`** 的 payload（只留标题/`public_title`）——牌堆顶 3 张是私人信息，不能给所有人看牌面；配合既有的只读机制（`popup_readonly_changed`），别人只能看提示、拖不动、确认按钮禁用。
- 客户端 `_on_prompt_sync()` 新增 `"reorder"` 分支：只有 `can_answer` 才 `send_answer("reorder", order)`；主机 `apply_net_answer()` 新增 `"reorder"` → `_on_reorder_answered()`。
