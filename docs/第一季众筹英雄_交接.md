## 五、踩过的坑（务必遵守，否则会浪费大量时间）
1. **不要用 PowerShell 多行字符串替换**改 `game.gd`/`Board.gd`/`Setup.gd`（缩进/换行差异会静默匹配失败 → 反复试错）。**一律用精确编辑工具**，并且 old_string 要连同上下文一起给（本会话有 1 次因注释里"行动牌/行动卡"一字之差而匹配失败）。
2. 每次改完立刻跑 `--import` 抓 `Parse Error`（廉价保险），为 0 才继续。
3. 测试用 `& devtools/run_tests.ps1 -Tests <名字> -LimitSec 150`（注意：本机只有 Windows PowerShell 5.1，`pwsh` 命令不存在，直接 `&` 调用脚本即可）。
4. 导出后**必须**用 exe 目录为 CWD 启动自检（`Start-Process -WorkingDirectory build`）；`data/` 与 `pck` 必须同目录。
5. `assets/cards/...` 新增 PNG 后要 `--import` 一次再跑游戏，否则贴图加载失败。
6. **测试里自己接 `Events.prompt_action` 等信号时，回调前必须 `await get_tree().process_frame`**：`_ask_action()` 是"先 emit 再 `await _answered`"，回调若同步执行会在 await 注册前就把信号发出去 → `await` 永不返回 → 看门狗判定卡死。照抄 `tests/newvillain_effect_test.gd` 的写法。
7. **效果内部的行动结算不要用 `_execute_attack/_execute_move/_execute_heroic` 的原始形式**（它们末尾会调 `_maybe_auto_end_turn`，符号已用尽时会提前结束回合、截断后续效果）。本会话加了 `state["in_effect"]` 总开关：`trigger_effect` 进来置 true、末尾（以及 3 个 shield 提前 return 分支）置 false，`_maybe_auto_end_turn` 见到就 return。**新加带提前 return 的效果分支时，记得同样复位 `in_effect`**。
8. **效果驱动的移动/攻击消耗传 `"none"`**：`_refund_symbol` 新增了 `"none"` 分支（什么都不归还），否则玩家在弹窗里点"返回"会凭空多出一个行动。
9. 用 `Game.setup(villain, heroes, "none", "base")` 直接造局（同步、不走 `start_game`），再手工设 `state["phase"]="hero_actions"`、`effect_available/played_effect` 后 `await Game.trigger_effect()`，是最省事的单效果测试姿势。
10. **`Game.setup` 抽的 6 个地点是随机的**：测试里依赖"回合结束效果"做判断时会被随机地点干扰（有的地点结束效果会抽牌 → 手牌不为空 → 该 KO 的情况不发生，测试就时红时绿）。做法：给该地点放一张无名威胁卡（`{"name":"测试占位","hp":0,...}`），`end_turn` 就会跳过地点结束效果。见 `tests/cull_ko_test.gd` ③。
11. **不要用 `h["ko"]` 判断"刚刚是否 KO 过"**：KO 的英雄会在**自己回合开始时复活**（`_start_hero_turn` → `_revive_hero`），反派回合结束后这个标记可能已经变回 false。改用"KO 日志"或事件判定。
12. **Godot 4 的 `TextureRect` 没有 `alignment` 属性**，赋值会报错并**中断所在函数**（返回 null）。本会话就在 `PopupLayer._make_action_row` 里踩到：所有带 `bottom` 缩略图的行（= 全部"选目的地"的弹窗选项）全部消失。改弹窗相关代码后跑 `tests/popup_rows_test` 兜底。
