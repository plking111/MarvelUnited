## 0. 一句话概括

犀牛人的核心机制是**「危机指示物」**（复用引擎既有的 `hero.crisis`，没有新增数据结构）：

1. **英雄被 KO 时，犀牛人不激活他的 BAM！**，改为**该英雄获得 1 个危机指示物**；
2. **身上有任何危机指示物的英雄，下一回合打牌必须正面朝下**（复用语引擎既有的 `forced_face_down_hero` 机制），
   然后在该回合结束时**丢弃所有危机指示物**；
3. **面板 BAM！的伤害 = 他本回合进入的地点数量**（所以 4 张「犀牛充电」行动卡会先走到英雄所在处，再按走过的格数撞人），
   然后把这些英雄**顺时针移动 1 个地点**；
4. **溢出** = 抽 1 张反派行动卡面朝下加入故事情节；
5. 6 张威胁卡（**开阔地带 ×3 + 无掩护 ×3**，都是"无生命值 + 3 个英勇槽"）在制造危机指示物。

### 2.4 与 docx（`devtools/犀牛人_docx原文.txt`）的出入 —— **本批 docx 没有实质规则冲突**

docx 是直接从 `新建 Microsoft Word 文档.docx` 里解 `word/document.xml` 出来的纯文本（同 `康_docx原文.txt` 的做法）。
逐条对照后，**卡图与 docx 的规则内容一致**，只有 5 处**文字/写法**问题（全部按卡图落库）：

1. docx 里 **8 处 `BAN！`** 是 `BAM!` 的输入错误（泽莫、摩多克两批同一个毛病）→ 统一按 BAM! 处理。
2. docx 的 BAM 文案写「**照成**等同于本回合犀牛人移动地点数量的伤害」→「造成」的错字。
3. docx 的特别规则写「……必须正面朝下添加在故事情节中，**任何**丢弃所有的危机指示物」→
   面板/规则原文是「**然后**丢弃他们所有的危机指示物」（**这条会影响实现时机**，见 §7 待裁定 ⑤）。
4. docx 的放置图案写成「**民暴/民暴/民暴**」（无分隔），卡面是三格各"1 暴徒 + 1 平民" → 已按三槽落库。
5. docx 的威胁卡段落把 6 张列成"开阔地带/无掩护"各 3 遍而**没有说明为什么重复**；
   卡图逐张核对后确认**确实是 3 张重复卡**（不是抄漏、也不是 6 张不同的卡）。
6. docx 只写了「顺时针：移动到下一个有英雄的地点」，**没有给出卡名「犀牛充电」**（卡名只在卡图上）。

**卡图优先的一个小补充**：docx 在 BAM 文案里多了括号「（溢出的伤害忽略掉）」，面板原文写的是
「**对犀牛人所在地的每个英雄造成 1 点伤害，等于他本回合进入的地点数量**」+「然后顺时针移动所有**受到伤害的**英雄 1 个地点」。
本实现按**面板**落库，并把"多余伤害忽略"交给引擎既有的"伤害按手牌数封顶"口径（见 §7 待裁定 ①）。

关键实现点：

- `_rhino_bam`：伤害 = `state.rhino_moved_locs`；**伤害为 0 时直接返回**（没人"受到伤害"→ 不移动任何人）；
  随后把**仍未被 KO** 的在场英雄用 `game._set_hero_loc(hid, next_live_loc, "forced")` 顺时针推 1 格
  （`"forced"` = 不是英雄自己移动，与秃鹫 BAM 的"被吹飞"同一口径，仍算"进入一个地点"）。
- `_rhino_overflow`：从 `master_deck` 抽 1 张，`story.append({type:"villain", face_down:true, idx:-1(宝石卡)或牌下标})`；
  牌堆空时只打日志、不报错（同神秘客溢出的写法）。
- `_rhino_on_ko`：`hero.crisis += 1`，**不触发任何 BAM**。
- `_rhino_start_turn`：`crisis > 0` → `state.forced_face_down_hero = hid` + `state.rhino_face_down_discard_hero = hid`。
- `_rhino_on_hero_end_turn`：① 所在地点威胁卡是「无掩护」→ `crisis += 1`；
  ② 若本回合被要求面朝下出牌（`rhino_face_down_discard_hero == hid`）→ **丢弃全部危机指示物**并把标记清空。
- `_rhino_on_hero_damaged`：所在地点威胁卡是「开阔地带」→ `crisis += 1`。

## 7. 待用户裁定的规则点（**我没有自己编规则，以下是按卡面/面板直译 + 明确标注的口径**）

1. **"多余伤害忽略"的口径**：docx 写"溢出的伤害忽略掉"，面板只写"造成 1 点伤害，等于他本回合进入的地点数量"。
   我按引擎既有口径实现：**伤害按该英雄手牌数封顶，超出的部分不结转**（也就是"忽略"）。
   若本意是"伤害超过手牌数时**不算 KO**（不把人打倒）"，需要改 `_rhino_bam`。
2. **伤害为 0 时要不要移动英雄**：我实现为**不移动**（因为"没有人受到伤害"，而卡面说"移动**所有受到伤害的**英雄"）。
   若本意是"无论伤害多少，所在地点的英雄都要被推 1 格"，改 `_rhino_bam` 去掉 `dmg <= 0` 的早退即可。
3. **被这次 BAM 打倒（KO）的英雄要不要被推动**：我实现为**不推动**（已经出局，且 KO 会走特殊规则①）。
4. **"本回合进入的地点数量"怎么数**：我按 **`_do_villain_move` 实际走过的步数**累加
   （字典移动记 1 次；被"卡通蛛网"取消移动、或没找到符合条件的地点时**不计**；不含**出发地**）。
   若本意是"经过的**不同**地点数"或"含出发地"，需要改累加口径（`game.gd` 1767-1790）。
5. **危机指示物的丢弃时机**：我实现为"**被要求面朝下出牌的那个回合结束时**丢弃全部"（卡面"然后丢弃"）。
   若本意是"回合一开始就丢弃"或"每打出一张面朝下的牌丢弃 1 个"，需要改（`_rhino_on_hero_end_turn` ↔ `_rhino_start_turn`）。
6. **"下一回合打牌必须正面朝下"的范围**：我实现为"**整个英雄回合**都被强制面朝下"
   （与摩多克·心灵异能、秘密身份挑战共用 `forced_face_down_hero`，打出第一张后引擎会清掉该标记）。
   若本意是"只要身上还有危机指示物就一直面朝下"，需要改成按 `crisis > 0` 每张都判。
7. **面朝下出牌的英雄仍继承上一张英雄卡的符号**（引擎既有口径）：卡面只说"必须正面朝下"，
   我保持"面朝下的卡视为空白 → 不给自己卡上的行动，但仍继承上一张"。
   若本意是"完全没有任何行动"（连继承也取消），在 `_rhino_start_turn` 里外加 `state["no_prev_symbols"] = true`。
8. **「开阔地带」的判定地点**：我按"**该英雄受伤时所在地点**"，而**不是**"伤害来源地点"。
   如果某效果是"在别的地点造成伤害"，仍按英雄脚下那张威胁卡判定。
9. **「无掩护」的判定时点**：我放在 `end_turn` 的"地点结束效果**之后**"、按英雄**最终**所在地点判定。
   若本意是"回合开始时所在地点"，需要挪到 `_start_hero_turn`。
10. **6 张威胁卡都能被 3 个英勇行动清除**：我按卡面（底部 3 个星星白框）落库为 `clear=["heroic"×3]`，可用英勇行动化解。
    若这一批威胁卡本意是"**不可清除**的持续危机源"，需要在数据里改成不带 `clear`（或加 `unclearable`），并同时改测试。
11. **`constant: true` 只是文档字段**：引擎里**没有任何代码读 `constant`**（grep 确认）。本批「开阔地带」是持续被动、
    「无掩护」是回合结束触发，卡面都没有徽标区分，实现是靠**卡名**在 `VillainRules` 里判定。
    如果希望"新反派不许按卡名判定"，需要给威胁卡数据新增一个显式字段（如 `passive_damage_crisis` / `end_turn_crisis`）。
12. **犀牛人没有专属失败条件**：面板没有"邪恶计划"轨道，所以 `plot_track: none`、`fear_track_max: 0`。
    如果规则书另有"危机指示物累计到 N 就判负"之类的条件，请告知（现在**没有任何**专属判负点）。
13. **卡 1~4「犀牛充电」在数据层没有 `effect`**（用 `move: {dir:"cw", hero_in:true}` 表达），
    因此 `VillainRules.resolve_effect` 里没有 rhino 分支、卡名不出现在数据/故事区文本里。
    若要求"卡名必须能在数据层看到/在日志里显示"，需要新增 `rhino_charge` 效果类型（引擎已经按 `move` 字段移动过，
    效果函数里**不能**再移动一次，只能打日志）。
14. **危机指示物目前是"无限叠加"**：面板没说上限，我按"每触发一次 +1"实现（与泽莫/克莱文一致）。
